DE CRM — Quick Reference
========================

REPO LAYOUT
-----------
  web/      The whole app, port 3000
              src/app/          pages + the API catch-all at /api/**
              src/server/       the API: routes, lib, db, agents
              src/server/http/  the small router that replaced Express
              drizzle/          SQL migrations
  (api/ is gone — the Express service was folded into web/, Render retired)
  project docs/   architecture, data model, build plan
  Digital Edify Agentic CRM (standalone).html   original Subframe design


FIRST-TIME SETUP (already done — skip unless on a fresh machine)
----------------------------------------------------------------
  cd web && npm install
  copy web\.env.example web\.env.local   # then edit, fill passwords + keys
  cd web && npm run db:migrate           # creates the schema on Azure
  cd web && npm run db:seed              # loads tenant + 12 leads + agents


RUN LOCALLY (every day)
-----------------------
  One terminal — app and API together:
    cd web && npm run dev              # http://localhost:3000
                                       # API at localhost:3000/api/health

  (Optional) DB browser:
    cd web && npx drizzle-kit studio   # https://local.drizzle.studio

  No background worker process any more. The three scheduled jobs are
  ordinary endpoints — trigger them when you need them:
    curl -H "Authorization: Bearer $CRON_SECRET" localhost:3000/api/cron/campaigns
  (campaign dispatch also fires automatically on launch/resume)


DB COMMANDS (run from web/)
---------------------------
  npm run db:check     ping Azure + list installed extensions
  npm run db:migrate   apply pending schema changes
  npm run db:seed      reset tenant data + reload all rows (idempotent)
  npm run db:reset     drop public schema. Then migrate + seed.


EDITING THE SCHEMA
------------------
  1. Edit web/src/server/db/schema.ts
  2. cd web && npx drizzle-kit generate   # writes new SQL into drizzle/
  3. npm run db:migrate                   # applies it


AZURE DATABASE
--------------
  Server:    de-crm-pg.postgres.database.azure.com
  Region:    Central India
  Version:   PostgreSQL 17, Burstable B1ms (~$15/mo)
             NOTE: Burstable caps near 35 connections and has NO built-in
             PgBouncer. That matters now the API is serverless — see
             DEPLOY.md, "The one thing to get right".
  Extensions enabled: pgcrypto, pg_trgm, vector
  Tables:    21 (full doc-03 model)

  Two roles (passwords in web/.env.local, NOT web/.env.example):
    decrm_admin   migrations + seed only (bypasses RLS — Azure default)
    decrm_app     the API connects as this role (NOBYPASSRLS, RLS enforced)

  Common gotcha: home Wi-Fi public IP changes, breaking the firewall rule.
  Fix: Azure Portal → de-crm-pg → Networking → "+ Add current client IP"
       → Save (button at top, not just the +Add).

QUICK TROUBLESHOOTING
---------------------
  "ETIMEDOUT 5432"           public IP rotated. Re-add IP in Azure Networking.
  "type vector does not exist"   extension allowlist not saved. Server params → azure.extensions.
  ".env not loading"         confirm web/.env.local exists (not .env.example).
  "drizzle studio: schema not found"   run `npm run db:migrate` first.
